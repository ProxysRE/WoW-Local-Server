# WoW Bestiary 0.4.0 — добыча и карта редких существ

Первая серверная версия справочника для WoW 3.3.5a. Бестиарий включён в актуальную
ветку `feature/wardrobe` вместе с AC Wardrobe. Основа гардероба — commit
`0d3e18f919b22e47ab457c3e10e3b96db83c0484`; ядро `be923cbc`, Playerbots `63a27bf0`.
Оба модуля собираются в один worldserver.exe. Ветка `feature/server-bestiary`
и её прежние артефакты не являются актуальной сборкой общего сервера.

## Что уже реализовано

- Все регионы с постоянными точками появления в загруженном каталоге ядра:
  Восточные королевства, Калимдор, Запределье, Нордскол, подземелья, рейды,
  поля боя/арены и остальные карты. Существ без добычи также включаем.
- В списке локаций — поиск, категории и прокрутка; названия приходят с сервера.
  Эльфийские и дренейские стартовые зоны относятся к своим континентам через
  виртуальную карту DBC, несмотря на внутренний map=530.
- Отдельные списки подземелий/рейдов для поддерживаемых режимов. Маска спавна
  отсекает существ из другого режима; шаблоны сложности выбираются с тем же
  порядком замены, что и в Creature::InitEntry ядра. Размер рейда берётся из DBC,
  поэтому старые рейды на 20/40 не подписываются как 10/25.
- Обычные, элитные, редкие и редкие элитные существа; альтернативы multispawn.
- Определение зоны по координатам через MapMgr, без зависимости от `creature.zoneId`.
- Русские названия из локализации сервера, уровни, ранги, число записей появления.
- Обычная добыча, снятие шкур и карманная кража, включая кандидатов из ссылочных таблиц.
- Поиск, сортировка по уровню/имени, фильтр ранга, подсказки предметов.
- Фильтр добычи по качеству (серые/белые/зелёные/синие/эпические и далее),
  поиск по имени/ID предмета и объединение повторяющихся путей одного предмета.
- Увеличенный интерфейс: размеры и число видимых строк зависят от UIParent;
  на маленьком экране применяется масштаб, удерживающий окно в пределах экрана.
- Карта живых позиций для подходящих редких существ открытого мира (см. ниже).
- Постраничный обмен по addon self-whisper, ограничение частоты запросов,
  сборка частей ответа, защита от устаревших ответов, тайм-аут.
- Аддон больше не требует Python, MySQL-пароля или выгрузки `Data.lua`.

## Установка на текущий сервер

Эта инструкция предполагает, что обновление Core + Playerbots из указанной основы
уже установлено. Если оно ещё не установлено, сначала выполните его инструкцию
`CORE_PLAYERBOTS_UPDATE_RU.md`: старому ядру могут требоваться SQL-миграции.

После успешной компиляции ветки `feature/wardrobe` скачайте общий артефакт
**WoW-Wardrobe-Update-x64-N**. Пакет содержит гардероб и бестиарий.

1. Установите обновление по инструкции `WARDROBE_RU.md` через `Install-Update.ps1`.
2. Скопируйте обе папки из `Client/Interface/AddOns` — `ACWardrobe` и `WoWBestiary` —
   в `<папка игры>/Interface/AddOns`. Не запускайте старый экспорт поверх новой версии.
3. Для карты установите сервер и аддон версии 0.4.0 вместе: сервер передаёт
   доступность отслеживания в списке существ и обрабатывает запросы позиции.
   Старый аддон 0.3.x не понимает новую запись списка.
   Новый аддон 0.4.0 совместим со старым сервером сборки №14 для списка/добычи:
   фильтры, очистка подсказок и размер окна работают, кнопка карты пока скрыта.
4. Запустите сервер. В логе должна быть строка
   `Bestiary: loaded ... creature templates across ... regions/modes`.
5. Войдите в игру и откройте `/wb`. Дождитесь загрузки списка локаций,
   выберите регион и существо,
   дождитесь загрузки добычи. Проверьте три вкладки.

Сам бестиарий не создаёт и не меняет таблицы БД и не требует новых настроек конфигов.
Ему нужен штатный addon-канал сервера. При отсутствии модуля аддон покажет тайм-аут.
Кнопка «Обновить» повторно читает серверный снимок; после редактирования БД или
`.reload` нужен перезапуск worldserver для обновления снимка бестиария.
Кэш аддона хранится только до смены мира/перезахода, поэтому данные другого сервера
не будут подмешаны. В памяти — максимум шесть недавно открытых регионов и
добыча шестнадцати недавно просмотренных существ; большой мир не загружается
целиком в аддон. Выбранная локация
остаётся настройкой, а данные лута — нет.

## Как читать лут в этой версии

Процент у простой строки — **базовый шанс этой строки БД**, без рейтов сервера,
проверки условий на персонаже и изменений от сторонних скриптов.
Для групп, ссылок, условий и нестандартных режимов итоговый процент пока не
вычисляется: поле оставлено пустым. Служебные цепочки из подсказок скрыты.
Один предмет показывается один раз; несколько путей не считаются независимыми
и не складываются. Если предмет встречается несколькими строками, его суммарный
шанс также остаётся пустым. Эффективные вероятности с рейтами/скриптами — будущий этап.

Лут читается фиксированными SELECT при запуске; запросы игроков не идут в MySQL.
Проверка валидности строк делегирована `LootStoreItem::IsValid` закреплённого ядра.
Для ссылок есть защита от циклов и предел глубины 16; каталог более 8191 строк
одного существа отклоняется явно с `CATALOGUE_LIMIT`, а не молча обрезается.

## Карта текущей позиции

Кнопка появляется только для редкого/редкого элитного существа (rank 4/2)
открытого мира, у которого больше одной постоянной точки появления либо в
записи спавна задано движение. Обычные мобы, простые элитники, подземелья и
неподвижный редкий моб с одной точкой не получают кнопку.

Сервер ищет только существ, уже находящихся в загруженных областях: живых,
присутствующих в мире, с нужным NPC ID и пересечением фаз персонажа.
Он не загружает карты/гриды и не активирует пулы ради запроса. Позиция берётся
из текущих координат самого существа, а не из точки рождения.

Точки рисуются на карте из ресурсов клиента 3.3.5, без изменения обычной карты
игрока. Имя текстуры читается из существующего `dbc/WorldMapArea.dbc` при запуске.
Если файл/карта недоступны, живой маркер не выдумывается. Если есть позиции в
нескольких зонах, используется кнопка «Следующая карта».

Обновление ручное, максимум раз в три секунды. Карта показывает возраст снимка;
через 30 секунд метки скрываются до нового запроса. Отсутствие живой позиции
не объявляется доказательством смерти: возможны выгруженная область или
неактивный пул. Точный таймер возрождения и полный анализ условий пулов/событий
не добавлены. Чисто скриптовое движение с movementType=0 само по себе пока не
делает моба подходящим, если точка спавна у него одна.

## Ограничения и игровая проверка

Добыча не фильтруется по текущему состоянию боя/дополнительным LootMode скриптов.
Полный анализ пулов/событий и эффективные вероятности ещё не реализованы.
Счётчик появления показывает записи постоянных спавнов, а не число живых мобов.
Чисто скриптовые призывы без постоянного спавна в каталог не попадают.
Локации без постоянных спавнов в загруженной БД также не выводятся.
Для режима, использующего отдельный шаблон сложности, карточка показывает
исходный NPC ID и ID шаблона; добыча читается из выбранного шаблона.

Проверить в клиенте: список регионов и русский поиск по ним; все континенты;
классический рейд на 40, рейд 10/25 обычный/героический, подземелье обычное/героическое;
переключение локации во время загрузки, прокрутку и выбранный режим;
поиск существ; ранги; моб без лута; качества и поиск предмета;
размер окна на своём UI-масштабе; живой редкий моб с маршрутом/несколькими точками,
пустой результат карты, смену фаз, обновление позиции и исчезновение метки через 30 секунд;
обычная добыча/шкуры/карманы; переключение существ во время загрузки;
повторное открытие окна и `/reload`; подключение без модуля и кнопка «Обновить».
Автотесты проверяют C++/Lua-протокол под Lua 5.1. Проверка заголовков ядра и
Windows-компиляция не заменяют запуск в игровом клиенте.

## Сборка

`scripts/prepare-sources.py` копирует `overlays/mod-bestiary` в `core/modules`.
Модуль собирается автоматически штатной системой модулей AzerothCore.
Общий пакет `Update_Wardrobe` содержит оба аддона и один сервер со всеми модулями
основы. Отдельный EXE-пакет бестиария больше не выпускается.
Дополнительного Eluna/AIO или патча клиента не требуется.

Код сервера распространяется под GPL-2.0-or-later; интерфейс продолжает
WoWBestiary 0.1.2 из этого проекта. AzerothCore и Playerbots сохраняют свои лицензии.

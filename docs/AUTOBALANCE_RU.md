# AutoBalance: численность группы в подземельях и рейдах

Используется azerothcore/mod-autobalance, ревизия
1d707cb61a0962ab01e4123681e2d3b66cc558a2 (2026-10-07).
Исходники и лицензия включены в полную сборку.

## Установка обновления

1. Остановить worldserver и сохранить копию старого worldserver.exe.
2. Скопировать Server/worldserver.exe в папку сервера.
3. Скопировать Server/configs/modules/AutoBalance.conf в configs/modules сервера.
   Нужен именно .conf, одного .conf.dist недостаточно.
4. Запустить worldserver. SQL, authserver и данные карт менять не нужно.

В EXE включены все прежние модули, временная прогрессия и исправления
сбора ресурсов/такси Playerbots. Старые конфиги других модулей сохраняются.

## Выбранный профиль

- Масштабирование включено для обычных и героических подземелий и рейдов,
  включая форматы на 5, 10, 15, 20, 25 и 40 персонажей.
- Минимум для расчёта — один персонаж. Остальные коэффициенты сложности
  оставлены стандартными для закреплённой версии AutoBalance.
- Считаются персонажи, вошедшие в конкретный экземпляр подземелья,
  а не все участники группы, находящиеся снаружи.
- Playerbots являются персонажами Player и учитываются как участники.
  Игрок и четыре бота внутри — пять участников. Питомцы не добавляют игроков.
- Включённый GM-режим исключает персонажа из подсчёта. Для проверки выполнить
  .gm off до входа в инстанс; при переключении режима внутри выйти и войти снова.
- AutoBalance.LevelScaling = 0: уровни противников остаются исходными.
- AutoBalance.RewardScaling.XP = 0 и AutoBalance.RewardScaling.Money = 0:
  модуль не пересчитывает опыт и деньги; действуют обычные правила ядра,
  другие модули и настройки сервера.
- AutoBalance.reward.enable = 0: дополнительные жетоны за старый контент отключены.
- При изменении состава выводятся уведомления. Во время боя модуль удерживает
  нижний предел сложности: выход участника не обязан немедленно облегчить бой.

Полный конфиг с описаниями параметров — configs/modules/AutoBalance.conf.
Профиль сборки — profiles/autobalance.json. Снижение численности использует
кривую масштабирования: два игрока не обязательно означают ровно 40% здоровья.

## Проверка

Войти без GM-режима в подземелье одному, затем добавить ботов в тот же инстанс.
Для проверки рейдов повторить в рейдовом подземелье. Команды:

```
.ab mapstat
.ab creaturestat
.ab getoffset
```

.ab creaturestat выполняется с выбранным противником. Проверять количество
участников, коэффициенты здоровья/урона и сохранение исходного уровня моба.
После изменения конфига использовать .reload config; для сравнения сначала
выйти из боя. Для отключения — AutoBalance.Enable.Global = 0 и перезагрузка конфига.

Individual Progression продолжает управлять доступом к контенту и своими
поправками силы персонажей. Два модуля не гарантируют историческую сложность.
AutoBalance не переписывает тактики, число обязательных целей, рычагов и другие
механики, требующие нескольких участников; прохождение любого рейда в одиночку
не гарантируется. Совместная сборка и проверка в игре — отдельные этапы валидации.

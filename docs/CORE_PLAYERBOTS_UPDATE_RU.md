## SQL

Относительно прежних закреплённых ревизий:

- world: 25 новых файлов обновлений содержимого;
- characters: один файл, расширяющий recovery_item и создающий recovery_item_loot;
- playerbots: один файл текстов для Чёрного храма;
- auth: новых файлов обновлений нет.

Точный журнал — UPGRADE_MANIFEST.json. Фактически updater применит только те
обновления, которые ещё не отмечены в каждой базе. Это обновление существующих
баз, не их пересоздание. Полный старый дамп импортировать не нужно.

## Установка

1. Остановить worldserver и authserver. Дождаться закрытия соединений с БД.
2. Через Navicat экспортировать полные резервные копии acore_auth, acore_world,
   acore_characters, acore_playerbots: структура и данные. MySQL оставить включённым.
3. Полностью распаковать обновление в отдельную папку.
4. В PowerShell запустить из этой папки, подставив путь к существующему Server:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-Update.ps1 -ServerPath 'D:\YourServer\Server'
```

Скрипт сохраняет копии конфигов и заменяемых файлов в UpdateBackups. Он не
подключается к MySQL, не меняет пароли и не запускает сервер. Это резервная копия
файлов, а не баз данных. Любой уже существующий .conf сохраняется.

5. Запустить authserver и worldserver привычными BAT-файлами. Автоматический
   updater применит миграции из обновлённых Source/data/sql/updates и
   Source/modules/mod-playerbots/data/sql/playerbots/updates.
6. Дождаться строки ready, затем войти своим персонажем. При ошибке миграции
   не импортировать файлы вручную: сохранить полный текст ошибки и логи.

Клиент, Data, карты, персонажи и гильдии не заменяются. Пакет содержит новые EXE,
DLL, SQL-обновления и AutoBalance.conf на случай, если его ещё нет. Существующий
AutoBalance.conf, worldserver.conf и playerbots.conf установщик не перезаписывает.
Папка Source объединяется с существующей; её старое содержимое не удаляется.

После SQL-миграции откат требует совместимых старых файлов И резервной копии
баз. Одной замены EXE для отката недостаточно.

## Конфиги

В ReferenceConfigs находятся новые worldserver.conf.dist и playerbots.conf.dist
для сравнения. Не переименовывать их поверх активных конфигов.

Единственный новый ключ worldserver.conf:

```
ItemDelete.Disenchant = 0
```

Он отключён по умолчанию; отсутствие строки в старом конфиге допустимо. Если
включить, сохранение распылённых предметов требует ItemDelete.Method = 1;
также действуют фильтры качества/уровня предмета. Это не требуется для обновления.

В playerbots.conf новых ключей и изменений значений по умолчанию нет. Уточнено
поведение RandomBotTeleLowerLevel/RandomBotTeleHigherLevel для новой RPG-стратегии:
они теперь участвуют в допустимом диапазоне уровней мест охоты и концентрации
возле игрока. Ранее комфортный конфиг сохраняется, но поведение может отличаться.

## Проверка после установки

- Вход, вещи, банк и гильдия своих персонажей.
- Загрузка ботов, сбор руды/травы, обычное такси и посадка.
- .ip get, .ip temp status и возврат .ip temp off.
- .ab mapstat без GM-режима: игрок и четыре бота внутри должны дать пять участников.
- Ошибки: Server.log, Errors.log и Playerbots.log.

Наши автоматические проверки и компиляция не заменяют проверку на твоём мире.
